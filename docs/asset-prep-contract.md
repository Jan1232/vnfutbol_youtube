# Asset preparation contract

Asset sourcing and asset preparation are separate stages.

`assets/assets.json` stores editorial asset intent, source URLs, provenance and rights notes. Third-party photos and match footage must not be committed to the public repository merely because a source URL is known.

Local materialization lives under `.local-assets/<video-slug>/` and is ignored by Git.

## Local folders

```text
.local-assets/<video-slug>/
  inbox/       # files manually dropped in by the editor
  source/      # original downloaded/ingested files
  candidates/  # multiple candidates scraped/discovered from source pages
  prepared/    # normalized files used by the renderer
  previews/    # contact sheets / low-res review previews
```

The committed machine-readable result is:

```text
videos/<video-slug>/assets/prepared-assets.json
```

It stores metadata and local relative paths only; it does not make third-party media public.

## Source classes

### External media

Photos and videos sourced from FIFA, UEFA, clubs or media pages are external editorial material. The prep pipeline may discover candidates and prepare local copies only when explicitly requested. A source page is provenance, not proof of a reusable license.

### Render-only assets

Maps, diagrams, generic trophy icons, newspaper-style cards, text/stat graphics and similar channel-owned graphics are renderer specs. They do not need a downloaded file before timeline generation.

### Mascot assets

The visual plan contains `poseIntent` and `outfitIntent`. Local tooling resolves these into existing approved poses and deterministic outfit IDs. No new pose may be generated by the asset-prep pipeline.

For mascot variants:

```text
approved base pose + approved outfit layer = production mascot
```

`default-home` uses the base pose directly. Non-default outfits must either reuse an approved `variants.json` entry or produce one deduplicated generation job per `(basePose, resolvedOutfit)` pair.

## prepared-assets.json states

Recommended states:

- `READY` — usable prepared local file exists.
- `READY_RENDER_SPEC` — renderer-owned graphic, no file required yet.
- `READY_MASCOT` — approved/reusable mascot composition exists.
- `NEEDS_SELECTION` — candidates exist but a crop/frame/clip has not been selected.
- `NEEDS_SOURCE_FILE` — source is known but no local file has been materialized.
- `MISSING` — no usable source exists.
- `BLOCKED` — rights/policy/mask/variant issue blocks use.

Each prepared record should preserve:

```json
{
  "id": "asset-id",
  "status": "READY",
  "sourcePath": ".local-assets/.../source/file.ext",
  "preparedPath": ".local-assets/.../prepared/file.ext",
  "sha256": "...",
  "width": 1920,
  "height": 1080,
  "durationMs": null,
  "clipStartMs": null,
  "clipEndMs": null,
  "sourceUrl": "...",
  "rightsStatus": "..."
}
```

## Image preparation

Do not destructively crop originals. Store crop/framing as metadata where possible. Generate review previews/contact sheets. Prefer source images that are large enough for a 1920×1080 composition and keep important hands/trophies/numbers inside safe framing.

## Video preparation

Keep the source file untouched. Prepared excerpts should normally be H.264, 1920×1080, 30 fps, yuv420p, and no longer than required by the scene. Strip source audio by default because narration is the timing source of truth. Do not invent clip timestamps: if the correct moment has not been selected, mark `NEEDS_SELECTION`.

## Timeline gate

A final `timeline.json` may be built only after:

1. `audio/voice.json` has generated `startMs/endMs` values;
2. every required visual has a prepared state;
3. every mascot scene has a concrete approved base pose and resolved outfit;
4. unresolved external media is either replaced by a renderer-owned fallback or explicitly marked for editor review.

The timeline should reference asset IDs, not brittle absolute filesystem paths. A local resolver can map IDs to `.local-assets/.../prepared/...` when Remotion builds the draft.
